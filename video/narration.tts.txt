My dad is seventy-eight. He takes eleven prescriptions from four doctors, and I manage all of it from another city with a hand-written grid.
Last week a fifth doctor started him on ciprofloxacin. Nobody checked it against the warfarin.
Pillbox is a shared medication list for a caregiver and a pharmacist. Each gets an agent on the same page, with different tools.
Every flag it raises carries the exact sentence from the FDA label that caused it, with the label's set ID. The data is openFDA: sixty-four common geriatric drugs, about a thousand interaction sentences, pulled live with the query URL kept beside every number.
Here is the caregiver's window. I tell the agent: he started ciprofloxacin yesterday. It calls check interactions with add ciprofloxacin, before the drug is even on the list.
Two rows go red. Warfarin. Here's the sentence, verbatim, from the warfarin label, and the set ID that takes you to it. Nothing here is paraphrased.
Now the pharmacist's window, same list. DevTools, Application, WebMCP. Nine tools. Propose change and add counsel note are here. Accept change and add medication are not. The server enforces the same split on every write.
The pharmacist's agent proposes holding the warfarin until an INR check. A confirmation card. The pharmacist clicks confirm.
It lands in the caregiver's window over the live stream, with an Accept button the pharmacist never sees. The caregiver's agent calls accept change. Confirm. Warfarin is held, and the flags recompute against what's actually active.
The side effect report is a declarative WebMCP form. The agent fills it. A human presses Send.
And the round card prints: eleven medications, time of day, what's held, one page for the kitchen table.
It's not a diagnosis. It's the label, in the room, for discussion with a pharmacist, when two people need it. Only the caregiver accepts, only the pharmacist proposes, and the page itself declares what each agent can do.
That's Pillbox.
